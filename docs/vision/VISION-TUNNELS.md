## 1. Why this note exists

**Vertical and horizontal scale are not owned by this file.**  
They live on the system map and in [VISION-ASSEMBLY](VISION-ASSEMBLY.md):

- **Vertical** — truth home, projection, hop home, recursive support (org/realm).  
- **Horizontal** — place book (workload): bodies across hosts.

**Tunnels** name only the missing middle for the dream: **trusted reachability** so nodes may talk across the tree without turning Palm into a mesh of equal owners.

This is a **long horizon**. It is the practical answer that makes Grove *feel* like one fabric while the soul stays a tree.

**Not this seed’s job:** open a theme, ship a commercial overlay network, redefine assembly, or be the sole home of scale vocabulary.

## 3. Phenotypes (same genome)

| Shape | Picture |
|-------|---------|
| **Small / all-in-one** | One process or one host; tunnels almost trivial (local doors). Company can work **without a dedicated server** if the working device stays online enough to be home or support. |
| **Cloud orchestrator** | Root light center in the cloud: assembly, claim, **tunnel mint**, who may exist. Stays efficient. |
| **On-device realm** | Phone, edge box, office machine — Palm (or thin Palm) with home up. Local ground when offline sector allows. |
| **Recursive realm** | Device is a **server**: support with children; same law deeper. |
| **Phone path** | App asks cloud → cloud grants tunnel to device realm → sync through path → contested truth still has a home. |

**Offline honesty:** a coworker’s sector may work offline on **local projection / local places** until home or peer path is back. Do not invent a second source of truth forever; **invalidate or reconcile** when home returns. Detail when theme opens.

**Data ownership dream:** small orgs own data on **their** devices and places; cloud is optional efficiency and tunnel broker, not forced landlord — if composition and trust say so.
